## Design Decisions
- Living header block (current status) + append-only dated log
- One file per project; archive folder for completed projects
- Filename convention: proj_[name].md
- Cowork mode (Claude Desktop) for file read/write operations
- PKM lives only on Google Drive; no separate version control
  (Drive's built-in revision history is sufficient)
- Operating Protocol governs session flow (see pkm_protocol.md):
  intake protocol, session-start protocol, active focus pointer,
  system-wide session log, end-of-session checklist
- **Storage architecture (decided 2026-05-10)**: Website projects
  live at `G:\My Drive\kimbridges-*` (Drive root); code-heavy
  projects live under `G:\My Drive\Projects\<name>`; the PKM itself
  lives under `G:\My Drive\Projects_Index\`. The deciding factor is
  product format: PDF / rendered-HTML outputs (often built outside
  the folder, e.g., from photo-publishing tools) go to the
  kimbridges-* family; .qmd/.R/code-as-source projects go under
  Projects/. This matches the categorical split already present in
  project_index.md (Website Projects vs Active R Projects). The
  rule defers the question of what to do with project types that
  fit neither bucket until one appears.
  **ANSWERED 2026-07-31 (Tier 3). Two more buckets appeared, and the rule
  above deferred exactly this question until they did.**
  - **Bucket 4 -- BUILD SCRATCH: `C:\temp\<name>_<date>`.** Rendered `_site`
    folders staged for a Netlify drag-deploy. They exist because a Drive-stream
    folder serves placeholders to the browser upload (Finding 008), and they are
    DATED because the R bridge cannot delete recursively, so overwriting in place

## System changes 2026-07-29
- **★ MECHANISM 6 ADOPTED — Deferred Work** (`deferred.md`). The protocol's first five
  mechanisms cover intake, context, focus, record and closing; none held **work that is real
  but not now**, which had nowhere to go but Next Steps, where it either manufactured urgency
  on a finished project or was silently dropped. Kim's proposal, prompted by the leftovers from
  the specimen_labels publication. **The design point: the file is the easy half, the trigger is
  the mechanism** — so Mechanism 2 gains the **project-touch rule** (read a project's deferred
  section before working on it) and Mechanism 5 gains **item 8** (file the non-urgent, clear it
  from Next Steps). Entries are split into **TASK** (waits for an occasion) and **CONDITIONAL**
  (surfaces only if a named thing happens, and arrives at the bad moment with the answer already
  written). Rules: items may be closed WON'T DO with the reason kept; deferred must mean "no
  occasion yet", never "unpleasant". One file with per-project sections, splitting to
  `deferred/<name>.md` only when a section earns it — the growth path the logs took on 07-28.
- **Two hazards met and queued as findings in `deferred.md`:** `writeLines()` on Windows rewrites
  every line ending (edit CRLF files in binary, verify the byte delta); and to force a fresh read
  over the device bridge, delete the local staged copy first, since staging alone may return the
  cached file. A character count is also not a byte count — comparing the two produced a false
  report of file instability, corrected in the record the same day.

**Three design decisions, each made against evidence rather than the original plan.**

*1. A mirror, not repos-in-venues.* The plan said "init one venue," which puts `.git`
on `G:` against bucket 5. A probe showed gert CAN init and commit on Drive Stream --
but operating today is not surviving Drive's sync lifecycle, so the rule stood. One
repo at `C:\repos\kimbridges-venues` mirrors source; the venues are untouched.

*2. A whitelist, not an ignore list.* VENUE_GITIGNORE missed `_output/` -- the
output-dir every Quarto book uses -- and admitted 2018 files of Jones research data
plus 278 rendered document pages. **A blacklist must anticipate every kind of junk; a
whitelist only has to know what source looks like.** `SOURCE_EXT` + `DERIVED_DIRS` +
`SOURCE_FILES` replaced it. `.html` is NOT a source extension: a first pass admitted
12.5 MB of R Notebook renders and htmlwidget maps living outside any build folder.
Only `viewer.html` is allowlisted, by name.

*3. Projects/, not just the venues.* Kim ruled out storing derived output, and applying
that to `kimbridges-documents` left 25 files -- the listing page and 22 cards. **The
documents themselves are rendered output copied in; their source lives in
`Projects/<name>`.** Mirroring venues alone would back up the shelf and not the books.

**The first push was REFUSED, and that was the best thing that happened.** GitHub push
protection found a live Anthropic API key in `Projects/LLM_API_R/Claude_API.qmd`,
commented out with `##`, dated April 2024. Never published (not a chapter of the
rendered `r_api` book -- checked three ways), but two years on disk with nothing ever
looking at it. Removed, replaced with `Sys.getenv`, local history rebuilt.
`pkm_secret_scan()` now runs before every commit. See Findings 027 and 028.

**New machinery in pkm_health.R:** `SOURCE_EXT`, `SOURCE_FILES`, `DERIVED_DIRS`,
`VENUE_SOURCE_ROOTS`, `.is_source()`, `.src_files()`, `pkm_mirror()`,
